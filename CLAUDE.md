# Fish and Run — BACKEND (game server)

Frontend (3D client) lives at `../Fish-and-run`. Colyseus + Mongo. (Reworked from the Bowling Roll / boat-race server, with Scare Your Neighbor's backend as the model for plots, presence, the `plot` relay, Offline Money and leaderboards. Package `fish-and-run-server`; the client's `GAME_SLUG` and the Legion game id (`LEGION_GAME_ID`) are `fish-and-run`.)

- `npm start` (tsx watch, port 2567), `npm run build` (tsc -> `build/`), `npm test` (mocha + `@colyseus/testing`, Mongo faked via `__setPlayersForTest` with `test/fakePlayers.ts`; tests share one booted server, `test/server.ts`). Node >= 22.
- One room, `world` (`src/rooms/WorldRoom.ts`, client calls `joinOrCreate("world", { userId, username, pfp, avatar, pose, loadout, base })`). **Room size = number of player plots**: `ROOM_MAX_CLIENTS` (`src/constants.ts`) = 8 = the client's `PLOTS.length` (3 west + 3 south + 2 east). Keep them equal; the deploy workflow reads that line and sends it as `roomSize` (valid 2-100, no `seatCap`). Each player gets one plot: roster `base` = the `base` the client asked for if free, else the lowest free index 0..7 (`assignBase`, presence.ts); freed when the player really leaves (consented leave, or the reconnect window ran out).
- Client-authoritative: the server only bounds/sanitises (`src/sanitize.ts`, `src/presence.ts`). `src/db.ts` degrades to "no persistence" when `MONGODB_URI` is unset/unreachable; guests (`guest-` ids) are never saved. `/health` for Legion; `/monitor` and the playground are dev-only.
- The client keeps NO progress in the browser: this server's Mongo doc is the player's only save. A guest's progress lasts the page only.
- Messages client -> server: `saveProgress` (whole snapshot, debounced client-side), `identify` (`{ userId, username, pfp }` after a sign-in/out), presence (below), `spin`, `claimDaily` { day }, `dailyRefresh`. Server -> client (private): `progress` (saved doc, sanitized, plus `offline`, `away`, `serverTime`), `noProgress` { serverTime } (new account / guest / no DB), `serverError` (save unreadable: saving stays off), `schedule` { eventEveryMs (5 h, `EVENT_EVERY_MS`), updateAt (ms, `UPDATE_AT_MS`), serverTime } (the HUD's "Next event in" / "UPDATE IN" countdowns run on the server clock), `leaderboard`, `spins`, `spinResult`, `daily`, `dailyResult`. Saves are ignored until the session's load has answered (`loaded`). A second live session on the same account is evicted.
- **Saved progress** (`PlayerDoc`, `sanitize.ts`; shape + bounds only): `money`, `gems` (0..`MONEY_MAX` 1e33), `trained` (trained speed stat, 0..`STAT_MAX` 1e15), `baseLevel` (base level: the client's pond slots + plot look, int 1..`LEVEL_MAX`), `treadmill` (int 1..`LEVEL_MAX` 100), `slots` (int active fish slots, 0..`SLOTS_MAX` 100), `fish[]` (the backpack, at most `FISH_MAX` 1000, each `{ species, weight (0..1e4 kg), earn ($/s, 0..MONEY_MAX), mutation ("" or id), equipped, hotbar }`; an entry without a species id, with a non-number weight/earn or a bad mutation is dropped), owned/equipped pairs `rods[]`/`rod` and `trails[]`/`trail` (the equipped id must be owned when the list is in the save, "" = none), `unlocked[]` / `claimed[]` (species ids, at most `SPECIES_MAX` 512 each), `income` (current $/s, plain `$set`), lifetime counters `caught` / `earned` / `playtime` (`$max`, so a stale save never lowers a leaderboard place). Server-only: `lastSeen`, `spins`/`spinAt`, `dailyDay`/`dailyLast`/`dailyClaimed`.
- **Offline Money**: the server stamps `lastSeen` on load, on every save and when the player leaves. On load `progress` carries `away` = seconds since `lastSeen` (capped at `OFFLINE_MAX_SECONDS`, 24 h; 0 if never seen) and `offline` = floor(`income` x `OFFLINE_RATE` (0.025 = client `ECONOMY.offlineRate`) x away); right after sending, the server re-stamps `lastSeen` so the time is counted once. The server does NOT add it anywhere: the client grants it.
- **Presence** (`src/presence.ts`, `test/Presence.test.ts`): what the others draw, relayed through the roster `PlayerState` (schema in `rooms/schema/WorldState.ts`), only bounded. Roster: `username`, `signedIn`, `pfp` (http(s) only, max `PFP_MAX_LEN`), `uid` (Bloxity user id, "" = guest), `base` (int16, -1 = none); pose `x`/`y`/`z`/`yaw`/`speed`/`vy` (float32), `grounded` (default true), `knocked` (thrown by a guard / lying on the ground); loadout `rod`, `trail` (ids, "" = none), `slot` (uint8: 0 nothing, 1 rod, 2 bat, 3 backpack fish), `item` (species in hand when slot = 3, else ""), `hold` (species just caught, carried overhead out of the lane, "" = none); `avatar` (Bloxity look JSON, opaque, max `AVATAR_MAX_LEN` 3000); `plot` (JSON object string, max `PLOT_MAX_LEN` 4000). Messages: `pose` { x, y, z, yaw, speed, vy, grounded, knocked } (~12/s; `POSE_BOUNDS` |x|,|z| <= 2000 (the lane runs to z = -975), |y| <= 200, speed 0..400, vy +-400, yaw wrapped to -PI..PI); `loadout` { rod, trail, slot, item, hold } (ids match `ID_PATTERN` or ""; slot an integer 0..3; anything else ignored per field); `setAvatar` { avatar }; `plot` { plot } (must parse as a JSON object, else ignored). The join options may carry `pose`, `loadout` and `avatar` too.
- **Bat bonks** (`src/bonk.ts`, `BONK` in constants, `test/Bonk.test.ts`): `swing` { target? } (at most one per `BONK.cooldownMs`) is relayed to everyone else as `swing` { id }; a target passes `bonkRefusal` when both players are out in the lane (z < `BONK.laneZ`; the hub is a safe zone), within `range` + `slack` m, the attacker holds the bat (slot 2), carries nothing and isn't knocked, and the target isn't knocked and wasn't bonked by this same attacker in the last `immuneMs` (10 min, per attacker-victim pair) and nobody was bonked in the last `shieldMs` (5 min shield for the victim against everyone, drawn as a bubble by the client). The room then gets `bonk` { by, to, x, z (flight direction), fish (the target's `hold`, "" = none), byName, toName }; the target's `hold` is cleared and `knocked` set at once. The victim answers `giveFish` { weight } (bounded, within `giveMs`, once) and the attacker gets `gotFish` { species, weight, from }. Client tuning: `BAT` in `../Fish-and-run/src/config.js`.
- **Leaderboards** (`src/leaderboard.ts`, `test/Leaderboard.test.ts`): top `LEADERBOARD_SIZE` saved players by each of `LEADERBOARD_STATS` (`income`, `caught`, `earned`, `playtime`), one process-wide cache refreshed at most every `LEADERBOARD_EVERY_MS`; own rank = countDocuments(stat > theirs) + 1 (null for guests / no score). `leaderboard` { boards: { stat: [{ name, value }] }, ranks: { stat: n | null } } is sent after each load and to everyone every `LEADERBOARD_EVERY_MS`. `connectDb` creates a descending index per stat.
- **Bloxity trophy boards** (`src/platformBoards.ts`, `PLATFORM_BOARDS` in constants, must match the client's `LEADERBOARDS`): `saveProgress` queues the saved `income` / `caught` / `earned` per user; every 30 s they go to `{BLOXITY_API_URL}/v1/leaderboards/hosted/{BLOXITY_GAME_ID}/report` as `legion_<id>` (`#m...` stripped; guest/dev ids skipped). A no-op without `BLOXITY_REPORT_TOKEN` + `BLOXITY_GAME_ID`. `test/PlatformBoards.test.ts`.
- **Spin wheel** (`src/spin.ts`, constants `SPIN_*`; kept for a future feature, the client has no wheel yet): server-authoritative. Each session's `{ spins, nextAt }` lives in `spinStates` (from the doc's `spins`/`spinAt`; a new player gets `SPIN_START`), one free spin per `SPIN_EVERY_MS` up to `SPIN_CAP`. After the load the server sends `spins` { spins, nextAt, serverTime }; `spin` answers `spinResult` { ok, id, spins, nextAt, serverTime } or { ok: false, reason: "loading" | "none" } and writes `spins`/`spinAt` itself.
- **Daily Reward** (`src/daily.ts`, `DAILY_DAYS`; kept for a future feature): server-authoritative on the server's UTC clock. Doc fields `dailyDay`, `dailyLast`, `dailyClaimed[]`, written only by `saveDaily`. On load today unlocks (`rollDaily`) and the client gets `daily` { unlocked, claimed, nextAt, serverTime }. `claimDaily` { day } answers `dailyResult` { ok, day, reason?: "loading" | "locked" | "save", ...view }; `dailyRefresh` re-rolls after midnight and answers `daily`.
- `src/constants.ts` bounds must cover the client's `src/config.js` (ids match `ID_PATTERN`). **A contract change goes in both projects** (this server and `../Fish-and-run`).
- CI/CD: `.github/workflows/deploy.yml` tests on PRs and pushes to `main`/`dev`; pushes also build+push a GHCR image and deploy to Bloxity Legion (`main` = prod, `dev` = dev), sending `roomSize` = `ROOM_MAX_CLIENTS`. Needs repo var/secret `LEGION_GAME_ID` and secret `LEGION_DEPLOY_TOKEN`. Legion injects `PORT`, `MONGODB_URI`, `CLIENT_ORIGIN`.
- **Bloxity room directory** (`src/legion-room-reporter.ts`, started from `src/index.ts` after `listen`; copied from Scare): every ~2 s posts this pod's rooms to the matchmaker (`MATCHMAKER_REPORT_URL`, `BLOXITY_REPORT_TOKEN`, `BLOXITY_GAME_ID`, injected by Legion) so Open Rooms / friend joins / join-by-id find them; a no-op locally.
